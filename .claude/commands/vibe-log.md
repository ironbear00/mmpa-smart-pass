현재 작업 내용을 `docs/VIBE_CODING_LOG.md`에 Decision 또는 Troubleshooting 항목으로 추가합니다.

## 입력 파싱

슬래시 명령 뒤에 인자가 있으면 그것을 항목 내용으로 사용합니다.
인자가 없으면 아래 두 가지 방법 중 하나로 파악합니다:
- 이전 대화 맥락에서 방금 마무리된 작업 내용 추출
- 사용자에게 "어떤 내용을 기록할까요? (Decision / Troubleshooting)" 질문

## 항목 종류 결정

| 단서 | 종류 |
|------|------|
| "결정", "선택", "~로 변경", "~를 채택", ADR | **Decision** |
| "오류", "에러", "안 됨", "깨짐", "실패", "해결" | **Troubleshooting** |

## Decision 형식

`docs/VIBE_CODING_LOG.md`의 `## 의사결정 (Decision)` 섹션에 추가합니다.

```markdown
### D-{다음번호}: {제목}
**날짜**: {오늘 날짜 YYYY-MM-DD}
**맥락**: {왜 이 결정이 필요했는가}
**결정**: {무엇을 결정했는가}
**근거**: {왜 이 방향을 선택했는가}
**결과**: {결과 및 관련 파일}

---
```

## Troubleshooting 형식

`docs/VIBE_CODING_LOG.md`의 `## 트러블슈팅 (Troubleshooting)` 섹션에 추가합니다.

```markdown
### T-{다음번호}: {제목}
**날짜**: {오늘 날짜 YYYY-MM-DD}
**증상**: {어떤 오류/이상 현상이 있었는가}
**원인**: {근본 원인}
**해결**: {어떻게 해결했는가}
**관련 파일**: {파일 경로}

---
```

## 번호 채번 규칙

1. `docs/VIBE_CODING_LOG.md`를 읽어 기존 `D-NNN` / `T-NNN` 항목 중 가장 큰 번호를 확인합니다.
2. 다음 번호 = 최대값 + 1, 3자리 zero-padding (`D-006`, `T-004` 등).

## 파일 수정

- 기존 파일을 덮어쓰지 않고, 해당 섹션의 마지막 `---` 뒤에 새 항목을 삽입합니다.
- 섹션이 없으면 파일 끝에 섹션 헤더와 함께 추가합니다.
- 수정 후 "D-006 항목이 추가되었습니다 (`docs/VIBE_CODING_LOG.md`)" 형식으로 보고합니다.

## 주의

- 날짜는 오늘(`currentDate`)을 사용합니다.
- 내용이 불분명하면 추가하기 전에 반드시 확인 질문을 합니다. 추측으로 작성 금지.
